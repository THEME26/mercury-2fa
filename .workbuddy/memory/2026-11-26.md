## v0.4.0 加密保险库落地（同日）

- 版本定为 0.4.0 而非 0.5：v0.3 自动填充未做，编号要如实反映缺口。
- 加密栈：hash-wasm 4.13 的 Argon2id 派生 KEK（m=19/64/256MiB，t=2/3/4），KEK 包住随机 DEK，AES-GCM-256 加密条目；参数写在密文头。
- **偏离原设计**：DEK 放 `chrome.storage.session` 而不是 offscreen document。理由：同为内存态、关浏览器即失、其他扩展读不到，省掉消息中转；`CryptoHost` 接口保留，等剪贴板回清/自动填充需要 offscreen 时替换实现。
- 逻辑分层：`lib/vault-service.ts` 注入 KeyValueStore + CryptoHost + 时钟，全部可单测；popup 与 SW 各自实例化，共享 storage，不走 runtime 消息，避免 polyfill 回调语义坑（`@wxt-dev/browser` 就是 `globalThis.chrome`，无 polyfill）。
- 测试 73 项：HOTP 10 组、TOTP 18 组、otpauth 10、crypto 11、service 17、importers 10。crypto 覆盖错误密码、单字节篡改、IV 不重复、密文不含明文。
- 迁移码解析：手写 varint reader（约 90 行）替代 protobufjs，测试里用独立编码器构造字节流验证。
- 浏览器实测手法：静态服务 + localStorage 版 `chrome.storage` 桩 + 注入脚本自动填表单，走完「设主密码→建库→加三条→取码」，用无头 Chrome 截图。同法在 `script-src 'self' 'wasm-unsafe-eval'` 下验证 wasm 未被 CSP 拦截，这是 MV3 最容易被漏的运行时坑。
- 界面截图存 `docs/screenshot-0.4-{lock,list,settings}.png`；踩到的视觉问题：过期码仍显示旧数字（改为显示占位）、置顶星标 0.4 透明度太淡。
- 未做：自动填充（需 host_permissions + 真实页面回归）、截图二维码（captureVisibleTab + zxing-wasm）、剪贴板回清（需 offscreen）、图标与上架。
