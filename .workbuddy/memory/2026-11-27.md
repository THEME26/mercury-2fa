## v0.5.0 交付（提交 129c3e9）

### 自动填充
- 权限模型：`activeTab` + `scripting.executeScript`，manifest 无 `host_permissions`、无常驻 `content_scripts`。安装面板只显示「读取当前标签页」。
- 注入函数 `lib/fill/autofill.ts` 必须自包含（被序列化进页面，不能引用模块作用域）。参数只传已算好的验证码，页面侧拿不到种子/DEK。
- 识别打分：autocomplete=one-time-code(100) / 含 otp|code(60~90) / inputmode numeric+maxlength4-8(60) / 关键词(50) / 表单含密码框(+20) / pattern 数字(+20) / maxlength==digits(+20)；阈值 60。type=password、hidden、不可见一律排除。
- 四层兼容：原生 setter 绕 React 受控输入、递归 shadowRoot、六格拆分（同容器 4~8 个 maxlength=1 且无其他字段）、祖先链 hidden 检测。
- 站点匹配 `lib/fill/site-match.ts`：注册域(手写二级后缀表) + issuer 归一化(去公司后缀) + 分词 + 编辑距离 ≤2；≥70 分才当默认项。
- UI：底部「填入 <发行方>」主按钮 + 行尾 ↵ 手动指定；填入成功后 700ms 关 popup。

### 备份格式（用户明确否决与 MercuryLock 共用）
- 独立格式 `{format:'mercury-2fa-backup', version:2, exportedAt, entryCount, vault}`，不与其它项目共用，互通走适配器。
- 错误分级 `BackupError`（json/magic/version/structure）：损坏、非本扩展、版本过新、内容不全、密码错，五类可区分。
- `openVault` 分级：DEK 解包失败 → 密码错；解包成功但 payload 解不开 → 内容损坏。`isWrongPassword` 兼容 VaultError 与 OperationError。
- `VaultV2.entryCount` 明文条目总数，每次 saveVault 更新，恢复时核对。

## 踩坑
- executeScript 的 func 会被序列化，任何外部引用都会在页面里 ReferenceError。
- AES-GCM 认证失败无法区分密码错与密文被改，必须按解密阶段分级，否则截断文件会被误报成密码错误。
- jsdom 里 offsetWidth/clientWidth 恒为 0，可见性判断要用祖先链 getComputedStyle + `documentElement.clientWidth > 0` 开关。

## 11:20 v0.7.1 修「加密进程未就绪」

现象：Edge 加载未打包扩展后，popup 显示「加密进程未就绪，请重试」。

实测（headless=false 也复现，非 headless 特有）：
- Edge 158.0.4370.33 的 offscreen 文档里 `chrome` 只有 `loadTimes`、`csi`、`runtime`，`chrome.storage` 为 `undefined`；同一份 offscreen.html 当普通标签页打开时 API 齐全。最小复现扩展（仅 storage+offscreen 权限）同样如此，与本项目代码无关。
- 因此 `lib/browser-store.ts` 顶层 `browser.storage.local` 抛 `Cannot read properties of undefined (reading 'local')`，offscreen 监听器没挂上，ping 40 次全空 → 2s 后报未就绪。
- 另测：offscreen 内 `navigator.clipboard.writeText` 必报 `Document is not focused`；`document.execCommand('copy')` 返回 true，清空走兜底路径可用。
- offscreen → SW 的 `chrome.runtime.sendMessage` 可用，`sender.url` 为 `chrome-extension://<id>/offscreen.html`。
- Chrome 158 stable 已移除 `--load-extension`，无法用同一探针在 Chrome 复现。

改法：新增 `lib/store-bridge.ts`，offscreen 用代理存储把所有读写发回 SW；background 只认 sender.url 以 offscreen.html 结尾的 `target=store` 请求；browser-store 改成调用时才取存储区。

验证：146 项测试、tsc 0 错、Edge 实机建库→加 GitHub→界面显示 702400 与本地 RFC 6238 一致。

探针留在 `.probe/`（已 gitignore）：`cdp.mjs` 浏览器级 CDP、`ui-e2e2.mjs` 真实 UI 全链路。

## 12:20 「wants access to this site」提示溯源

用户问扩展为何反复显示 wants/has access。

定位：这两句是浏览器扩展菜单的站点访问状态行，不是扩展 UI。证据：
- 源码与 `.output/*/manifest.json` 全无该文案；产物 permissions 仅 7 项，无 host_permissions / optional_host_permissions / content_scripts。
- Edge 158 en-US.pak @450992 连续出现 `Wants access to this site` / `Has access to this site` / `Click to allow "$1" on $2` / `Allowed to read & change`，同块邻居为 `Site access`、`Pin to toolbar`、`Remove extension` → 属扩展菜单卡片。zh-CN 对应「想要访问此网站 / 可以访问此网站」。
- 探针：`.probe/siteaccess.mjs`（headed Edge + `--load-extension`，Edge 保留该开关；Chrome 158 已移除）、`.probe/grep-ui-strings*.mjs`（二进制/ pak 文案定位）。

结论：activeTab 状态机。未授予本站点 → Wants access；点图标/快捷键授予当前标签页 → Has access；刷新、跳转、换标签页回到前者。与主密码无关，popup 挂载即调 `getActivePage()`，解锁只控制「填入」按钮出现。

顺带记录：PowerShell 从 Bash 调用被安全策略拦截，`Add-Type` 亦被拦，全屏截图不可用；CDP `Page.captureScreenshot` 只覆盖页面内容，不含浏览器 chrome UI。
